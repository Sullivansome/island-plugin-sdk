# Island design contracts

`crates/island-design` is the toolkit-free source of logical-point geometry and shared tokens. GPUI (macOS/Windows) and GTK (Linux) consume it; core uses its motion duration. Native bridges use the same outline for hit testing.

| Token/contract | Value or behavior |
| --- | --- |
| Compact content | 245 × 24 logical points (Spotify contract, not a universal plugin size) |
| Generic default | 380 × 160; manifest preferred size initializes each surface |
| Preferred size limits | Width 64–512, height 20–256 logical points |
| Detached collapsed pill | 185 × 32 |
| Notch ears / content inset | 44 / 16 points; content starts below measured safe area |
| Attached outline | Black; concave top corners, rounded bottom corners |
| Attached corners | Top 6→10, bottom 14→20 points, clamped to available geometry |
| Detached outline | Radius half height; shared sampled circular corner geometry |
| Primary / secondary text | #f5f5f7 / #98989e |
| Motion | 420 ms quadratic ease-in-out, interruptible and idempotent |
| Frame format | BGRA8, tightly packed physical pixels, maximum 2048 × 1024 / 8 MiB |

The host owns chrome, placement, queue selection, animation intent, user collapse, and the content rectangle. Plugins own pixels inside that rectangle. Both shells interpolate the core expand factor. Native hit regions track the visible outline rather than the maximum transparent host bounds. An active expanded/peek Present clears manual collapse; compact presentations and frames preserve it.

Hover entry uses a 350 ms dwell inside the painted outline; exit collapses hover presentations. On macOS, one native pointer sampler owns hover and click-through, including while the window ignores mouse events. It converts AppKit view coordinates to top-left logical points using the fixed host bounds and the view's flipped orientation. Dwell is evaluated on its 16 ms sampling tick, independently of plugin frames or the host maintenance timer. Toolkit mouse events still route plugin input but do not override native hover.

The shared component contracts are `IslandHost` (native overlay), `IslandPill` (shape and transition), collapsed metadata (leading/trailing label and status), and expanded plugin surface (pixels, input, focus, cursor). The expanded slot shows a plugin frame or empty chrome — shells do not draw host-owned music, notification, or timer cards. Native companion controls expose previous/play-pause/next and enablement through accessible toolkit controls or menus. A framebuffer is not a semantic accessibility tree; future plugin-defined accessibility nodes must extend the shared protocol.

Check collapsed, compact and generic maximum sizes on notch/non-notch displays, plus scale changes and native input routing. Automated geometry/interaction coverage and physical-display validation limits are recorded in `docs/architecture-review.md`.

## Market

Agent Pulse uses the shared `hover` presentation mode: it expands after pointer dwell and collapses when the pointer leaves, even after a click. Priority and sticky lifetime keep attention available without opening the panel. New requests, completions, and failures never auto-expand it. Other plugins retain the `expanded`, `compact`, and `peek` modes. Core owns this policy for both shells; macOS supplies native pointer presence even when the panel is click-through. On notched Macs, collapsed metadata occupies two 38-point ears outside the camera. The provider icon is on the left and an amber ! marks pending input on the right. Expanded content starts below the measured camera safe area.

Codex permission hooks run before a reviewer decides and do not identify whether that reviewer is a person or automatic review. Show **Checking permissions** with the normal working indicator and priority, then plain **Working** when later activity arrives. Unmatched approval bookkeeping never adds an amber badge, a warning label, or attention priority. Matching completion or a turn boundary clears that bookkeeping. Explicit question tools still show **Needs you** during unrelated work; asynchronous question-tool returns do not resolve them. The fixed header retains the attention count while browsing. Hook-only monitoring cannot reliably identify Codex manual approval prompts; do not infer a per-task reviewer from global configuration.

Agent Pulse content is 340 points wide. A single session is 88 points tall; two sessions are 140 points. Longer lists use a 192-point panel with a 156-point scrolling viewport beneath the fixed 28-point header. All sessions participate in one continuous list of 52-point rows, clipped to that viewport. Wheel/trackpad scrolling moves content without changing selection; a 3-point scrollbar with a 12-point hit area supports dragging and track clicks. Arrow, Home/End and Page Up/Down navigation reveal the selected row. Live updates preserve the first visible session where possible; closing rows clamps the offset. Bundled Codex, Claude, and Grok provider artwork identifies each row and connection. The portable collapsed metadata can carry a validated BGRA icon up to 96 × 96 pixels, shared by GPUI and GTK. The macOS renderer uses the system San Francisco font, with platform system-font fallbacks. Titles are 14 points, secondary labels 11; row selection, pointer hover, pressed controls, and keyboard focus use distinct rounded treatments. Working uses a small monochrome progress indicator; attention is amber, completion a green check, and error red. Indicators always accompany text. No elapsed-signal counter or persistent management footer appears in the main view.

Sessions needing input sort ahead of working sessions. The entire list scrolls in priority order; waiting sessions begin at the top without consuming permanently pinned rows. A new request returns to the top of the session list and selects the highest-priority waiting session. Repeated updates do not steal selection. Waiting for a person has no ten-minute inactivity downgrade: retain that explicit request until a resolving lifecycle event, verified terminal closure, or the existing 24-hour retention limit. Grok's bounded active-session registry removes abandoned sessions after a 30-second registration grace period. Unreadable or malformed registries never imply disconnection. PermissionDenied resolves waiting; scheduled wakeups and background tasks do not turn a finished foreground turn into Working.

The Agent Pulse list contains open sessions. `SessionEnd` removes a row; `Stop` only marks a turn ended. On macOS and Linux, terminal hooks record the agent ancestor's PID, process birth token and controlling terminal. A missing/exited process, recycled PID or detached terminal removes its row on the next refresh without waiting for a final hook. The terminal app's lifetime is not used: another tab can remain open. Process-inspection errors preserve the row. Desktop tasks without a terminal are governed by lifecycle hooks. Older records acquire terminal tracking on their next hook; no process ownership is guessed from a project name. A new turn replaces the old terminal identity when a task is resumed elsewhere.

Clicking a row or pressing Enter opens its session. Up/Down select rows; scrolling moves the viewport without opening or selecting sessions. Codex desktop uses its exact task URL; macOS CLI hooks record the owning application with PID and process-start identity, so terminal sessions return to the original application. Terminal tab selection is not guessed. Older records without an origin expose Copy resume command instead. The overflow view offers Open session, Copy resume command, and Connection settings. Connections uses three provider rows in a 248-point surface. Each row separates verified hook installation from the latest recorded activity; installation alone never means connected, another provider's activity never implies Codex is reporting, and old sessions never imply current reception. No recorded signal is a neutral waiting state, not a repair warning. Hook trust is not inferred or changed. Setup controls say Install hooks, Repair setup only for verified incomplete configuration, or Reinstall hooks when already installed. Empty, waiting, loading/disabled, read-error, and copy-success states are explicit. The host URL permission gates opening a session; only the exact `codex://threads/<UUID>` application route is allowed, without query strings, fragments, or commands. Native activation uses the same launch permission, validates the recorded process identity against PID reuse, and never launches a shell command. The hook receiver still records no prompts, transcripts, or full project paths.

Agent Pulse colors and geometry live in `island_design::agent_pulse`; other colors inherit native Island tokens. The renderer emits the same portable frame on each shell. Working animation renders only while expanded, at most once per 120 ms. Collapsed status uses the normal one-second observation tick. The short compact preview and all expanded previews come from the actual renderer with labeled sample sessions.

Main-session lifecycle and stale-state rules live in the toolkit-free Agent Pulse model. The host retains presentation arbitration, collapse, geometry, and OS window policy. Hook setup is explicit, additive, and separate from plugin startup; receiving a frame never configures another application. `Stop` is labeled “Turn ended,” not “Goal complete.” The first-run surface explains how to connect; installed-but-quiet state asks the user to start a task instead of assuming hooks are untrusted.

On macOS, an explicit click can make the nonactivating panel key; passive presentations still do not activate the app. This permits plugin arrow-key/Tab navigation and the host's Escape-to-collapse action. Attached/notched collapsed chrome draws status in the ears outside the camera; both shells expose the status to accessibility.

Plugin websites may use their own identity, including Spotify's charcoal/green standalone site. Market renders reviewed Plugin Website v1 text, feature rows, captions and links with the native tokens below. Plugin HTML/CSS is not embedded. The Island companion website retains the shared charcoal/blue identity; web-specific typography and responsive spacing live in each site's token file.

On macOS the native menu-bar icon exposes Settings → About Island, Market, and Quit. About uses the standard system panel with release version and license; Market reuses its existing window. App-menu actions match the status menu, with ⌘⇧M for Market and ⌘Q for Quit.

Both GPUI and GTK implement a visual storefront with Discover and My plugins. The visual direction is modern minimal: a compact catalog heading, understated text navigation, and one horizontal featured listing followed by a responsive card grid. A plugin's name, monogram, categories, and description establish its identity; publisher, availability, and the detail action sit in a separated footer. Monograms are explicit fallbacks, not invented brand logos. Search and category filters preserve their state when returning from a detail page. Cards show only real catalog entries, with an actual filtered result count. Each opens a dedicated page with a back action, description, preview, installation/runtime controls, and a collapsed technical-details section.

Previews belong on plugin detail pages. Author screenshots load asynchronously with byte/dimension limits and explicit loading, unavailable, failure, and retry states. Spotify includes compact and expanded captures from its actual renderer using original sample copy; both are labeled as sample content. Viewing any preview never starts or installs a plugin. The same read-only media loader serves both shells.

Installation and update review is a dedicated page that retains verified provenance, digest, and all requested/new capabilities. Navigation cannot abandon a pending review; approve or cancel returns to the selected plugin. Removal retains its keep/delete-data choices. Bundled plugins expose Disable instead of Remove. Preview loading is independent of package operations.

My plugins also exposes a native folder picker for local installation through the same review flow. Incompatible installed packages remain visible with a Needs update label, an explanation, and replacement/removal controls; Enable and Retry are unavailable until the package is compatible. Local installation returns to the unfiltered My plugins collection.

Market tokens live in `island_design::market`. Surfaces use neutral charcoal with no green tint: background #151515, controls #222222, featured cards #252525, and preview canvas #303030. Primary text is #f5f5f7 and secondary text is #a6a6ad. Navigation uses a light underline for its active collection, including on detail pages. Filters and preview selectors use a neutral #363636 selected surface; selection is distinct from focus. Blue is reserved for links (#80b4ff), immediate 2-point focus rings (#a8cbff), and primary actions (#245cc5 with light text). Hover surfaces, pressed states, text selection, error, and warning colors also come from shared tokens. Both shells use the same state palette, including search selection. Normal text and action-label combinations meet 4.5:1 contrast; focus rings meet 3:1 even against a hovered blue action.

Default window is 1000 × 740 logical points, minimum 720 × 520; page inset is 32 and preview stage is 240 high. Titles use 32 points, featured plugin names 36, card titles 22, body 14, and supporting labels 12. Feature/detail/grid monograms use 104/72/48-point squares. Cards have 16-point corners and a quiet #303030 divider; controls are 38 points high. Preview selectors appear above the image, beside the section label; sample captions remain below. The storefront adapts between two and three columns. Native search, focus navigation, readable empty/error states, and cached discovery remain available.

Hallmark refinements follow this locked native system. Rust tokens are the portable source for GPUI and GTK CSS; unused web token exports, web fonts, decorative artwork, and page entrance animations are not part of the companion UI. Native desktop QA covers default and minimum window sizes rather than mobile web breakpoints.
